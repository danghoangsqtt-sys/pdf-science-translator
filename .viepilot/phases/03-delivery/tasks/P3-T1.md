# P3-T1 — Offline Windows package and verification

## Objective
Chuẩn bị bản Windows kèm đủ runtime/data để chạy không cần cài công cụ AI riêng;
đo thực tế và bàn giao kèm bằng chứng, nêu rõ mọi gate chưa đạt.

## Paths
- scripts/build_offline_windows.py: portable Python 3.12, app resources and data assembly.
- webui/frontend/package.json: offline packaging resources/scripts.
- tests/test_offline.py: packaging contract and public-data tests.
- README.md: profile/offline instructions and limits.
- agent-knowledge/repository.md, agent-knowledge/pdf-engine.md, agent-knowledge/validation.md: new contracts.
- agent-knowledge/release.md: distinguish offline portable assembly from the legacy updater release contract.
- docs/bao-cao/offline-windows-2026-10-28.md: measured evidence and handoff.
- CHANGELOG.md: unreleased offline/profile changes.
- .viepilot/TRACKER.md, .viepilot/ROADMAP.md, .viepilot/HANDOFF.json: task state updates.

## File-Level Plan
- Use existing local interpreter/resources/models; verify hashes and runtime cloud-disabled support.
- New build output path only; no overwrite of user-installed apps or PDF output.
- Keep source weights/build/cache out of git. Ship local notices and data independently of identity-free UI.
- Measure real profile translations, cold first run, missing assets and preserved formula glyphs/render.
- Record checked status separately from unapproved commit/tag/push persistence.

## Best practices
Source hash immutable; no arbitrary recursive move/delete; no secret output;
static local frontend assets; packaged Python includes all native OCR/layout modules.

## Verification
- Full unittest, pip check, hard Ruff, frontend tests/build, app smoke.
- Fresh owned runtime using private data pack, no existing external AI service dependency.
- Actual PDF: page/canvas/markers/glyph checks and all-page render review.
- Windows package startup + local-only connections; no vendor identity in public DTO/UI/log.
